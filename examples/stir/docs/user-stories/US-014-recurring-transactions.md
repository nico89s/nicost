## User Story
**As a** user with recurring financial commitments (subscriptions like Netflix/Spotify, silent bank admin fees, monthly bills, salaries, and PayLater/installment dues),  
**I want to** easily register and manage automated recurring transaction rules directly from Quick Log or the Recurring Hub,  
**So that** my cash flow and monthly expense commitments are automatically recorded accurately without tedious manual entry every month.

---

## Acceptance Criteria

### 1. Unified Creation in Quick Log Modal (`[S08]`)
- [x] Quick Log modal contains a **`🔄 Jadikan Transaksi Rutin`** toggle available for all transaction types (`Pengeluaran`, `Pemasukan`, `Transfer`).
- [x] Selecting the recurring toggle reveals frequency options: `Harian (Day)`, `Mingguan (Week)`, `Bulanan (Month)`, and `Tahunan (Year)`.
- [x] Limit options are provided:
  - `Tanpa Batas`: Endless auto-execution until paused or deleted.
  - `Sebanyak X Kali`: Caps execution to a specified count (e.g. 12x).
  - `Sampai Tanggal`: Ceases execution after a specific date boundary.
- [x] Saving creates the immediate transaction for today in the ledger and schedules future executions in `RecurringRule`.

### 2. Cicilan (Installments) Auto-Linking
- [x] Adding an installment in `[S12B] Cicilan Hub` automatically schedules a monthly recurring rule with `limit_type: 'count'` set to total tenor months and execution count set to paid tenor count.
- [x] Paying a monthly installment manually from Cicilan Hub advances the recurring rule's schedule and execution count.
- [x] Deleting an installment removes its associated recurring rule.

### 3. Background Auto-Execution on App Launch
- [x] On app launch or page mount, `executePendingRecurringRules()` checks all active rules with `next_run_date <= today`.
- [x] Past-due cycles are generated sequentially into the ledger with `is_recurring: true`, deducting wallet balances accordingly.
- [x] The schedule advances to the next period with defensive month-end clamping (preventing JavaScript 31st date overflow).
- [x] Rules reaching their limit are automatically deactivated.

### 4. Smart Edit Propagation on Latest Generated Transactions
- [x] Editing an older historical recurring transaction modifies only that specific record in the ledger.
- [x] Editing the **latest generated transaction** of a recurring rule automatically updates the parent rule's template (amount, category, wallet, notes) for all future runs.

### 5. Visual Differentiator in Activity List
- [x] Transactions generated by recurring rules display a crisp circular badge with a circular arrow (`🔄`) at the bottom-right corner of the category icon across `[S04] Aktivitas` and `[S01] Beranda`.

### 6. Recurring Governance Hub (`[S14] /governance/recurring`)
- [x] Metric summary banner displaying Total Monthly Recurring Commitment ($IDR/bln$) and active rule counts.
- [x] Segmented type filter (`Semua`, `Pengeluaran`, `Pemasukan`, `Transfer`).
- [x] Cards showing category avatar, title, wallet, frequency, next due date countdown (`Besok`, `5 hari lagi`), and active switch toggle.
- [x] Action triggers for `+ Tambah Rutin` (opens Quick Log in recurring mode), `⚡ Jalankan Sekarang` (manual execution), and `🗑️ Hapus` (Form 2 Centered Dialog).
